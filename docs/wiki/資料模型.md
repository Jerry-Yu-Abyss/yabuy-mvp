沒有 schema 檔案——以下欄位是從程式碼裡實際的 `setDoc/addDoc/updateDoc` 呼叫回推整理的，非 Firestore 強制 schema。

## `users/{uid}`

| 欄位 | 型別 | 寫入者 | 說明 |
|---|---|---|---|
| `id` | string | `Landing.vue` `User.vue` | 等於文件 ID（uid），冗餘存一份方便查詢 |
| `displayName` | string | 同上、`List.vue` | 註冊時預設 email 帳號名；可在 `List.vue` 個人資料表單改 |
| `email` | string | 同上 | |
| `photoURL` | string | 同上、`List.vue` | 頭像存於 Storage `avatars/{uid}.jpg` |
| `status` | `'active' \| 'banned'` | `Admin.vue` | 停權由管理員在用戶管理分頁設定；`App.vue` 登入時檢查，`banned` 會被強制登出 |
| `verify` | `'google' \| 'email' \| 'not_yet'` | `verify.js` 的 `syncVerifyStatus` | 單一寫入點，見 [[驗證與權限]]；只允許往「已驗證」方向更新，防止快取值把已驗證覆蓋回未驗證 |
| `isAdmin` / `isFounder` | boolean | `functions/addAdminRole` | 僅供後台列表顯示用的鏡像，實際權限判斷以 Firebase Custom Claims 為準 |
| `ratingSum` / `ratingCount` | number | `Deal.vue`（`increment()`）| 交易後互評的星等彙總，見下方 `reviews` |
| `cancelCount` / `cancelPeriodStart` | number / Timestamp | `Mailbox.vue` | 主動取消的額度，30 天 3 次、買賣共用；只有前端擋 |
| `expireCount` / `expirePeriodStart` | number / Timestamp | **Cloud Function `onOrderExpired`**（Admin SDK） | **面交爽約**：`accepted` 逾期時記給「沒按安全交易」的一方 |
| `noReplyCount` / `noReplyPeriodStart` | number / Timestamp | 同上 | **未回應**：`pending` / `negotiating` 逾期時記給沒回的一方；訂單成立不滿 12 小時不記 |
| `createdAt` / `lastLogin` | Timestamp | | |

## `orders/{id}`

交易的核心物件，狀態機見 [[交易生命週期]]。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `buyerId` `buyerName` `sellerId` `sellerName` | string | |
| `productId` `productName` `productPrice` `productImage` | | 下單當下的快照，非即時關聯查詢 |
| `location` `time` `originalTime` | string | `time` 格式 `YYYY-MM-DD HH:mm` |
| `status` | `'pending'\|'negotiating'\|'accepted'\|'rejected'\|'failed'\|'expired'\|'completed'` | `expired` = 逾期關閉，見 [[交易生命週期]] |
| `negotiationStep` | number | 賣家限改 1 次、買家限改 2 次（`Mailbox.vue` 前端擋） |
| `lastActionBy` | `'buyer'\|'seller'\|null` | 誰送出最後一次提案/取消 |
| `buyerReady` `sellerReady` | boolean | `Deal.vue` 面交確認就緒狀態。**兩支都 true 就等於「面交已開始」**，逾期判定會跳過這種訂單（掃碼、議價、互評本來就可能拖過 30 分鐘）|
| `buyerDelayUsed` `sellerDelayUsed` | boolean | 推遲面交時間的額度，買賣各 1 次。**規則層的 `delayUsedOk()` 有強制**：只能 false → true，且只有本人能立自己那一支 |
| `finalPrice` | number | 成交時填入 |
| `createdAt` `updatedAt` | Timestamp | |

## `settings/{docId}`

平台層級設定，目前只有 `settings/trade` 一份。一般使用者可讀（前端靠它決定要不要驗時段），只有管理員能寫。邏輯集中在 `tradeSettings.js`。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `enforceSafeHours` | boolean | 是否強制 06:00–18:00 的交易時段限制 |
| `simpleTradeMode` | boolean | 簡易交易模式（**預設開啟**）。目前管的只有一件事：面交流程跳過「掃描交易點 QR」那一站。開啟時整站跳過、時間軸少一站，完成畫面不再顯示實際地點／時間（那兩筆本來就是掃碼的產物） |
| `enforceQrScan` | boolean | 舊欄位，極性與 `simpleTradeMode` 相反。仍會被一起寫入，只是為了回滾安全；讀取時只在沒有 `simpleTradeMode` 時當作退路 |
| `updatedAt` `updatedBy` | Timestamp / string | 最後一次切換的時間與操作者 |

兩個開關都在管理後台「用戶管理」分頁切換（限創辦人），每次切換都寫入 `audit_logs`。

**兩個開關的失敗方向刻意相反。** `enforceSafeHours` 讀不到就當作限制生效（一律回到 `true`）——寧可擋住一筆合法交易讓人回報，也不要靜默把安全時段規則放掉。`simpleTradeMode` 讀不到則回到「簡易」——掃碼那站擋不住詐騙，它只是「有沒有到現場」的佐證，但沒貼 QR 的交易點或讀不到設定的裝置會被它整條面交流程卡死，連金額確認與互評都走不到。

程式碼裡 `enforceQrScan` 是由 `simpleTradeMode` 取反得出的 computed（`tradeSettings.js`），`Deal.vue` / `DealTimeline.vue` 讀的是它，不直接讀總開關——簡易模式之後若再省一站，那兩支不必跟著改。

## `messages/{id}`

面交前的罐頭訊息與推遲請求，UI 見 `CannedChat.vue`、邏輯見 `can.js`。文件本身沒存買賣雙方 uid，權限靠 `isOrderParty()` 回頭查 `orders`。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `orderId` `senderId` `text` `createdAt` | | 一般罐頭訊息只有這幾個欄位 |
| `kind` | `'delay'` | 只有推遲請求會帶；沒有這個欄位就當一般訊息渲染 |
| `proposedTime` | string | 提議的新時間，格式同 `orders.time` |
| `requestStatus` | `'pending'\|'accepted'\|'declined'` | 對方同意時，與 `orders.time` 在同一個 `writeBatch` 裡一起更新 |

## `reviews/{id}`

`Deal.vue` 的 `submitRating()` 成交後寫入，買賣雙方互評（不限賣家被評）。

| 欄位 | 說明 |
|---|---|
| `orderId` | 對應的 `orders` 文件 |
| `raterId` `ratedId` | 評價者 / 被評價者 |
| `ratedRole` | `'seller' \| 'buyer'`——被評價者當時的角色 |
| `stars`（1–5）`comment` | 文字評論**只**寫進 `reviews`，只有管理端讀得到，不會外流給對方 |
| `createdAt` | |

同時對 `users/{ratedId}` 執行 `increment()`：

- `ratingSum` += `stars`
- `ratingCount` += 1

前台個人頁（`User.vue`）只讀 `ratingSum/ratingCount` 算平均星等，讀不到評論文字。

## 複合索引（`firestore.indexes.json`）

| Collection | 欄位組合 | 用途 |
|---|---|---|
| `products` | `status ASC, createdAt DESC` | 首頁/搜尋列出上架中商品 |
| `products` | `category ASC, status ASC, createdAt DESC` | 分類篩選 |
| `products` | `sellerId ASC, createdAt DESC` | 個人賣場 |
| `orders` | `buyerId ASC, createdAt DESC` | 買入請求列表 |
| `orders` | `sellerId ASC, createdAt DESC` | 收到訂單列表 |
| `notifications` | `target ASC, createdAt DESC` | 系統公告 |
| `favorites` | `userId ASC, createdAt DESC` | 收藏列表 |
