# 驗證與權限

← 回 [[Home]]　｜　寫入哪個欄位見 [[資料模型]]

分成兩套完全獨立的機制：**信箱驗證**（決定能不能交易/上架）與**管理員權限**（決定能不能進後台）。

## 信箱驗證（`verify.js`）

單一事實來源，三態：

| 狀態 | 條件 |
|---|---|
| `google` | `emailVerified === true` 且 `providerData` 含 `google.com` |
| `email` | `emailVerified === true`，非 Google 登入 |
| `not_yet` | `emailVerified === false`（**不論**是否曾綁過 Google——這點曾是 bug，見下方修正記錄）|

### 關鍵函式

- `resolveVerifyStatus(fbUser)` —— 純函式，由 Firebase user 物件推導三態
- `ensureVerified(fbUser)` —— 交易/上架前的即時守門：先 `fbUser.reload()` 拉最新 `emailVerified`，reload 成功才回寫 Firestore（失敗的狀態不可信，不拿來寫資料庫）
- `syncVerifyStatus(fbUser, status)` —— **唯一**允許寫入 `users.verify` 的地方；規則：
  1. 文件不存在就不寫（建檔交給 `Landing.vue`/`User.vue` 的 `upsertUserDoc`）
  2. 狀態沒變不浪費一次寫入
  3. **禁止降級**：`isVerified(current) && !isVerified(status)` 時直接跳過——避免本機快取的舊 `emailVerified` 把資料庫裡已經正確的 `email`/`google` 打回 `not_yet`
- `sendVerificationThrottled(fbUser)` —— 重寄驗證信，**60 秒節流**（時間戳存 `localStorage`，key 為 `yabuy:verifyMailAt:{uid}`）。原因：Firebase 每寄一封新驗證信就會讓前一封的連結失效，短時間內連續觸發會讓使用者點到「已過期」的舊連結
- `blockUnverifiedForTrade(fbUser, toastFn, {resend, action})` —— 各頁交易/上架入口共用的攔截函式，未通過時顯示 toast 並視冷卻狀況決定要不要重寄

### 誰呼叫這套邏輯

| 檔案 | 用途 |
|---|---|
| `Landing.vue` / `User.vue` 的 `upsertUserDoc` | 建檔/登入時寫入初始 `verify`（含防降級）|
| `App.vue` | 每次 `onAuthStateChanged` 觸發時呼叫 `ensureVerified(user)`（背景執行，不 await）|
| `TradeModal.vue` `Home.vue` `Funnel.vue` `Book.vue` `Heart.vue` `User.vue` | 發起交易前呼叫 `blockUnverifiedForTrade` |
| `Cam.vue` | 上架前呼叫，`action: '發布商品'`（訊息文案跟著換）|
| `User.vue` 的 `refreshVerifyState` | 進到「我的」頁時主動 reload 一次，避免橫幅停在別裝置驗證前的過期狀態 |

## 管理員權限（Firebase Custom Claims）

不經過 Firestore 規則判斷身分，而是 **Custom Claims**（`admin: true` / `founder: true`），由唯一一支 Cloud Function 設定：

`functions/src/index.ts` → `addAdminRole`（Callable Function）

```
呼叫者未登入                → unauthenticated
呼叫者非創辦人且非管理員      → permission-denied
不帶 email（bootstrap 自己）：
  └ 呼叫者是創辦人 → 設自己 admin+founder；否則 permission-denied
帶 email（授權他人）：
  └ 只有創辦人能執行；創辦人本人的權限不可被取消
```

- **創辦人 email 寫死在程式碼**：`reso950211zxc@gmail.com`（`FOUNDER_EMAIL` 常數）
- `users/{uid}.isAdmin` / `.isFounder` 只是**鏡像**，方便 `Admin.vue` 的用戶列表顯示徽章，實際權限判斷永遠以 Custom Claims 為準（前端讀 `idTokenResult.claims.admin`）
- `Admin.vue` 的「確認我的管理員權限」按鈕就是呼叫 `addAdminRole` 不帶 `email` 參數，用於創辦人首次 bootstrap
