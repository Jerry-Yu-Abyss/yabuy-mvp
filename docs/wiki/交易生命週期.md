# 交易生命週期

← 回 [[Home]]　｜　欄位定義見 [[資料模型]]　｜　畫面見 [[元件目錄]]

一筆 `orders` 文件有兩層狀態機：**訂單狀態**（`orders.status`，跨頁面共用）與**面交當下的步驟**（`Deal.vue` 內部 `step`，只在面交流程中使用）。

## 第一層：`orders.status`（`Mailbox.vue` / `TradeModal.vue`）

```
                    ┌─────────────┐
    TradeModal 送出 →│   pending   │
                    └──────┬──────┘
             賣家「更改提案」／買家「再改一次」
                           │
                    ┌──────▼──────┐
              ┌────▶│ negotiating │◀────┐
              │     └──────┬──────┘     │
     再次改提案（步數上限見下）           │
              └─────────────┘            │
                           │ 對方按「接受」
                    ┌──────▼──────┐
                    │  accepted   │── 進入 Deal.vue 面交流程 →見下方第二層
                    └──────┬──────┘── 過約定時間 30 分鐘仍未開始 → expired
                           │
              ┌────────────┼────────────┐
        Deal.vue 判定失敗          雙方都同意成交
              ▼                          ▼
         ┌─────────┐              ┌────────────┐
         │ failed  │              │ completed  │
         └─────────┘              └────────────┘
```

另外三個終止態：

- **`rejected`**（顯示為「已取消」）——
  - 賣家在「收到訂單」按「婉拒」（`rejectOrder`）
  - **買家**在「買入請求」按卡片右上角 ✕ 自行取消（`cancelOrder`，`pending`/`negotiating` 狀態才會出現這顆按鈕），會多寫 `lastActionBy: 'buyer'` 標記是買家取消

- **`expired`**（顯示為「⏰ 已逾期」）—— 約定的那個時段過完 30 分鐘，這筆交易卻還沒走到該走的地方，任一方可按「逾期關閉」結案（`expireOrder`）。「該走到哪」隨狀態而不同：

  | 逾期前的狀態 | 什麼叫沒走到 | 記給誰 | 記在哪 |
  |---|---|---|---|
  | `accepted` | 雙方沒有**都**按下安全交易 | 沒按的那一方（都沒按就兩邊各記一次） | `expireCount` |
  | `pending` | 賣家從頭到尾沒回應 | 賣家 | `noReplyCount` |
  | `negotiating` | 協商到一半沒人接話 | 不是 `lastActionBy` 的那一方 | `noReplyCount` |

  兩組計數各自 30 天 3 次、各自獨立，但踩到任一條的後果一樣：暫時不能發起新交易。分開計數是因為「約好了卻沒出現」與「收到請求沒回應」嚴重性不同，不該加總。

  `pending` / `negotiating` 逾期時，卡片上原本的婉拒／接受／更改提案會整組換成「逾期關閉」——對著一個已經過去的時段按「接受」沒有意義。這種訂單沒有復活路徑（罐頭訊息只在 `accepted` 之後才有），買家回商品頁重新發起即可。

  **未回應記次有 12 小時下限。** 買家可以把面交時間填在半小時後，賣家根本來不及看到就逾期了；沒有這道下限，惡意買家連送三筆「馬上就要」的請求再自己關掉，就能把一個賣家刷到禁止發起交易。「沒出現」不設這道門檻——那是雙方都同意過時間之後的失約，與前置時間無關。

  逾期只是「還沒開始」的破局，不是「進行中」的失敗，所以判定刻意跳過 `buyerReady && sellerReady` 都為 true 的訂單——面交一旦開始，掃碼、議價、互評本來就可能拖過 30 分鐘。只有一方按下不算開始：那正是對方放鳥的情境，準時到場的人要能結案。

  時間到之後 `canStartSafeTrade` 會回 false（原本只有下界，時間過三天按鈕照樣是開的），`canCancel` 也會回 false——同一張卡片不該出現兩顆結果一樣、扣的額度卻不同的按鈕。

  **按下逾期關閉的人不會被扣任何額度。** 放鳥的是對方，卻要準時到場的人吐一次額度並不合理。爽約記在「沒按安全交易」的那一方身上——兩邊都沒按時兩邊各記一次。

  記次由 Cloud Function `onOrderExpired` 監聽 `status` 轉成 `expired` 後用 Admin SDK 寫入，因為前端寫不了別人的 `users` 文件。累計方式是 30 天 3 次（`users.expireCount` / `expirePeriodStart`），**滿 3 次就無法再發起新交易**，週期過完自動恢復，不需人工解鎖。

  這條額度是三種額度裡防護最完整的一種：`expireCount` / `expirePeriodStart` 已被列進 `users` 的 update 不可竄改清單，create 也擋掉夾帶，發起交易的閘門在 `orders.create` 的 `notExpireBanned()`。相對地 `cancelCount` 仍然只有前端擋。

  規則層唯一算不出來的是「過了 30 分鐘沒有」——`orders.time` 是不含時區的字串（見 [[新交易流程規格]] 風險 2），所以那段判定留在 `Mailbox.vue`，規則只保證終點合法（`accepted → expired`，且 expired 之後誰也改不動）。

### 改提案次數限制（前端擋，寫在 `Mailbox.vue`）

| 角色 | `negotiationStep` 上限 |
|---|---|
| 賣家「更改提案」 | 1 次 |
| 買家「再改一次」 | 2 次 |

## 逾期後還想交易：推遲面交時間

逾期不代表沒救。任一方可在罐頭訊息（`CannedChat.vue`）送出「⏰ 希望推遲至 X 點面交」，對方按同意後 `orders.time` 就會被改寫，逾期判定跟著新時間重算，「安全交易」按鈕自然復活。

- 額度：**買賣各 1 次**，記在 `orders.buyerDelayUsed` / `sellerDelayUsed`，與 `negotiationStep` 的改期額度分開
- 這條額度**規則層有強制**（`delayUsedOk()`）：旗標只能 false → true，且只有本人能立自己那一支。能歸零就等於無限推遲，可以把約定時間一路往後推、繞過逾期關閉
- 提議時間的限制（前端）：必須晚於現在也晚於原約定時間、24 小時內、06:00–18:00（最後一條與 `TradeModal.vue` 同一條規則）
- 訊息與額度旗標、同意與改時間，各自都用 `writeBatch` 綁成一次原子寫入——拆成兩次寫，任一次失敗都會留下爛狀態

## 第二層：`Deal.vue` 的 `step`（僅 `status==='accepted'` 之後才會進入）

```
verify ──雙方 buyerReady && sellerReady──▶ confirm ──雙方 buyerDeal/sellerDeal===true──▶ price（買家輸入金額）
  │                                          │                                              │
  │ 任一方 buyerDeal/sellerDeal===false       │                                     seller-confirm-price（賣家確認）
  ▼                                          ▼                                              │
status → failed，關閉視窗                 status → failed                                    ▼
                                                                                       status → completed
                                                                                       products.status → sold
                                                                                       雙方可各自送出評價 → reviews
```

- **scan**：雙方各自掃描交易點現場張貼的實體 QR（或手動輸入代碼），寫入 `actualLocationCode` 與各自的 `ScannedAt`。**這一站可以被管理端關掉**（`settings/trade.enforceQrScan`）——沒有實體 QR 的環境要能把面交跑到底。關閉時整站跳過、時間軸少一站，完成畫面也不再顯示「實際地點／實際時間」，因為那兩筆本來就是掃碼的產物
- **verify**（舊流程，已被 scan 取代）：賣家出示 QR（內容＝`order.id`），買家掃描或手動輸入前 8 碼比對，雙方各自按「就緒」
- **confirm**：雙方看到訂單摘要，各自表態「成交／不成交」（寫入 `buyerDeal` / `sellerDeal`）
- **price**：僅買家角色可見，輸入最終成交金額寫入 `finalPrice`
- **seller-confirm-price**：僅賣家角色可見，確認買家輸入的金額
- **done**：雙方都完成 → `orders.status = 'completed'`、對應 `products.status = 'sold'`，觸發評價 UI
