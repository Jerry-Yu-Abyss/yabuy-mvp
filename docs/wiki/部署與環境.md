## 開發環境

```bash
npm install                # 前端套件
cd functions && npm install && npm run build && cd ..   # Cloud Functions（獨立子專案）
npm run dev                 # Vite dev server，預設 http://localhost:5173
```

- **沒有 Firebase Emulator 設定**——本機開發時所有讀寫都是直接打正式的 Firestore / Auth / Storage，沒有隔離的測試環境。見 [[已知問題]]。
- `vite.config.js`：`@` alias 指向 `src/`；`server.host: true` 允許區網 IP 連線；手動加了 COOP/COEP headers（`same-origin-allow-popups` / `unsafe-none`，讓 Google 登入彈窗能正常運作）
- `.claude/launch.json`——本次協作新增，供 Claude Code 的預覽功能啟動 dev server（`npm run dev`, port 5173）

## 建置與部署

```bash
npm run build                        # 產出 dist/
firebase deploy --only hosting       # 部署前端

cd functions && npm run build && cd ..
firebase deploy --only functions     # 只有改到 functions/ 才需要
```

`firebase.json` 重點設定：

- `hosting.public: "dist"`，`rewrites` 全部導回 `/index.html`（SPA 路由）
- `functions.predeploy`：部署前自動跑 `npm run lint && npm run build`
- `firestore.indexes` 指向 `firestore.indexes.json`（見 [[資料模型]]）

## 本次協作觀察到的部署注意事項

- **瀏覽器快取**：Firebase Hosting 對 hashed 檔名的 JS/CSS 資源預設是長效快取，實測發現同一個分頁在 deploy 後直接重新整理，有時仍會吃到快取的舊 bundle。用帶查詢字串（如 `?cb=2`）的網址強制繞過快取最可靠。
- **一般開發流程**：這個 session 的模式是「改程式碼 → `npm run build` 確認無誤 → `firebase deploy --only hosting` → 瀏覽器實測 → 使用者確認後才 `git commit && push`」，commit 跟部署是分開兩件事，不預設綁在一起。
