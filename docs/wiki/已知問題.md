# 已知問題

← 回 [[Home]]

整理這次統整過程中發現、但**尚未修正**的技術債，供之後排優先順序。

## 1. `Heart.vue` 分頁不可達

`App.vue` 的頂部導覽列圖示曾把愛心（收藏）換成地圖（見對話記錄「Mailbox換圖示」那次改動），但 `activeTab === 'heart'` 這條路由沒有清掉——目前**沒有任何按鈕**會設定 `activeTab = 'heart'`。

- 功能本身沒壞：收藏清單仍可從 `User.vue` 的「喜愛」分頁使用
- 但 `Heart.vue`（265 行）連同它的 Firestore 監聽變成死碼，且 `App.vue` 裡 `activeTab !== 'heart'` 的判斷式也是死條件
- 建議：確認產品需求後，要嘛移除 `Heart.vue` 相關程式碼，要嘛在 `List.vue` 選單加一個入口

→ 詳見 [[導覽架構]]

## 2. 安全規則不在版本控制內

`firestore.rules` 與 `storage.rules` 都不存在於這個 repo，`firebase.json` 也沒有指向任何規則檔——代表規則是直接在 Firebase Console 手動編輯的。

- 沒有 code review 紀錄可查規則什麼時候改過、為什麼改
- 新環境/新開發者無法從 clone 這個 repo 重建出完整的安全設定
- 建議：`firebase firestore:rules` / storage rules 用 `firebase deploy --only firestore:rules,storage` 的方式納入版控

## 3. 沒有 Firebase Emulator

本機 `npm run dev` 的所有讀寫都直接打正式環境的 Firestore / Auth / Storage，沒有 `firebase emulators:start` 的設定。

- 本機測試（例如這次測「未驗證→驗證」交易流程）只能用真實帳號、真實資料庫，或手動用 REST API 造合成資料後再清除
- 建議：加 `firebase.json` 的 `emulators` 區塊 + `firebase init emulators`

## 4. 名不符實的 PWA

README 與 `Landing.vue` 都把專案定位成 PWA，並有「加入主畫面」教學影片，但：

- `public/` 沒有 `manifest.json`
- `main.js` / `index.html` 沒有註冊任何 service worker

嚴格來說目前只是「可以加到手機主畫面的一般網頁」，不是符合標準的可安裝 PWA（沒有離線快取、沒有 install prompt 觸發條件）。

## 5. 建置產物偏大

`npm run build` 持續出現這個警告：

```
(!) Some chunks are larger than 500 kB after minification.
dist/assets/index-*.js   ~769 kB (gzip ~259 kB)
```

單一 chunk，沒有做 code-splitting；另外 `src/assets/map/AU-Map-01.jpg` 約 4MB，直接原圖打包進 `dist/`，`MapPage.vue` 沒有壓縮或延遲載入。

## 6. `index.html` 還是預設模板

`<title>Vite</title>`，從未改成 `YaBuy`——瀏覽器分頁標題、社群分享預覽都會顯示錯誤名稱。

## 7. `Deal.vue` 除錯訊息量偏大

`Deal.vue` 的 `syncStep()` 等關鍵函式留了大量 `console.log/warn`（含完整訂單物件），正式站也會印出。內容不含密碼等機敏資訊，但會洩漏商品/交易細節到瀏覽器主控台。
